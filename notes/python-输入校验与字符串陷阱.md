## 一、今日踩的坑（本人填写）

> 每条写四件事：**现象 → 我当初以为是什么 → 实际是什么 → 以后怎么避免**。
> 至少覆盖下面三个坑；还有别的自己加。

### 坑 1：`isdigit()` 当门卫，把 `-40` 和 `3.5` 关在门外
（本人要点：isdigit 只判断字符串是否是非负整数。）
- **现象**：calculator.py 输 `-40`、`3.5` 被"请输入有效的数字"拦下——计算器算不了负数和小数，而代码里明明写着 `float()`。
- **我当初以为**：`isdigit()` 判断"是不是一个数字"。
- **实际是**：它判断的是**字符层**，不是数值层——整串必须全由数字字符组成（＝非负整数）才 True。`-`、`.` 不是数字字符所以被拦；反方向的边界更阴：`"²".isdigit()`、`"１２３"`（全角）都是 **True**，`""`（空串）是 **False**。
- **以后怎么避免**：用任何判断方法前先问"它看的是字符层还是数值层"；校验逻辑写成清单——"哪些输入必须拦、哪些必须放"——逐条实测。

### 坑 2：字符串不可变 —— `replace` 返回的不是"改好的原串"
（本人要点：replace 返回新建的字符串。）
- **现象**：converter.py 里摘除行 `checked = in_c.replace(".", "", 1).replace("-", "", 1)` 写在负号位置判断**之前**，却不出问题；我 9/3 口头答这题时先答反了（说"replace 改原字符串"）。
- **我当初以为**：replace 会原地改掉原字符串。
- **实际是**：字符串不可变，replace 只**新建并返回**新串；结果被 `checked` 接收，`in_c` 原封未动——后面 `count("-")`、`startswith("-")` 读到的位置信息完好。**代码的安全不靠行顺序，靠"不可变＋新变量接收"。**
- **以后怎么避免**：凡要用字符串方法的返回，就用变量接收；对"原值变没变"有一丝怀疑，就当场打印验证，不靠猜。

### 坑 3：沉默型 bug —— 不报错、输出也对，但那行代码从来没生效过
（本人要点：不报错、但代码逻辑有问题。9/3 遇到两处：）
- **① `num1 = float(num1)`"等于白写"**：它**干了活**（str→float 类型转换，没它计算器会把 `"1"+"2"` 拼成 `"12"`），但作为**错误防线**永远不生效——能走到这行的输入已被 `isdigit()` 限定为 `"42"` 这类纯数字字符的**字符串**（执行前是 str，执行后才变 float），`float()` 在这永远不可能抛 ValueError。真正的防线是上面那行 `if ... isdigit()`。
- **② `replace(...)` 结果没接收**：单独一行执行不报错，但原串纹丝不动——静默空转。
- **以后怎么避免**：每写一行"转换/修改型"代码，问两句——结果有没有被变量接收？我赋予它的职责它真能承担吗？改完校验必须拿"看着会溜过去"的边界输入实测（如 `1.2.3`）。

## 二、我自己定的校验规则（本人填写）

> 把三条规则写出来，并说明每条用哪个方法实现。
> **加分项**：说出你**故意**比 `float()` 更严格的地方（提示：`.5` 合法吗？`+5` 呢？），以及你为什么这么选。
> 记住：知道自己规则的边界在哪，比规则本身更值钱。

三道闸门（顺序即 converter.py 代码顺序，方法名全部来自本人口答）：
1. **数量闸**：`count("-") > 1 or count(".") > 1` → 拦。（用 `count` 判数量）
2. **字符闸**：用 `replace` 摘掉一个点和一个负号——**第三个参数 `1` 是保命符**（只摘第 1 个；不写就是把**所有**点都摘光，`"1.2.3"` → `"123"` → isdigit 通过 → 非法输入溜进 `float()`）——剩余部分再 `.isdigit()`。（用 `replace` 摘除＋`isdigit` 验剩余）
3. **位置闸**：`count("-") == 1 and not startswith("-")` → 拦，即负号只许在开头。（用 `count`＋`startswith` 判位置）

摘除写在判位置**之前**为什么不破坏判断：摘在 `checked` 新串上，`in_c` 不可变、原封未动（见坑 2）。

**加分项（故意比 `float()` 严的地方）**：`+5`——`float("+5")` 能成功（=5.0），但本规则拦（isdigit 不认 `+`）。

**边界实测（本人确认）**：口答时我说规则含"点不在开头和结尾"，但三道闸里**没有一条管点的位置**——`count(".") > 1` 只管数量、`replace(".", "", 1)` 摘掉一个后再 `isdigit()`、负号位置闸不涉及点。推理：`.5` → 摘点后 `"5".isdigit()` True → `float(".5")`=0.5 **放行**。**结论：我口答的规则与我的代码不一致——规则里没实现的一条，就是边界。** ① 终端实测结果：**放行**（`0.50 摄氏度 = 32.90 华氏度`，2026-09-03 本人终端实测）；② 一致吗：**不一致**；③ `+5` 干脆不认的一句话理由：因为 `isdigit` 不能通过 `+5`（本人）——再补一层：`float("+5")` 能成，放行它就得在规则里多一条"+ 只许在开头"，少认一种符号就少一类漏洞（AI 补）

## 五、读 traceback（2026-09-04 追加，本人填写）

> 提示框架（AI，非正文）：程序崩了之后——先看哪一行、拿到什么信息？再看哪一行、拿到什么信息？
> 多层调用链（好几个 File 行）时，真正的出错点是哪一个？最上面那个 File 行是什么角色？
> 第一行 `Traceback (most recent call last):` 有用吗？最后用 3 句话以内写完，能让自己下个月看懂即可。

> **誊写说明（2026-09-04）**：本节由 AI 誊自本人当日口答（Q9 补答＋3 场景实操＋费曼复述），
> AI 未加问答之外的内容（同 9/3 一、二节执行记录）。

- 先看最后一行：异常类型＋一句话消息（如 `ValueError: invalid literal ...`）；然后再往上看紧贴的 File 行，那就是真正出错的位置（文件·行号·那行代码）。
- 有好几个 File 行时：紧贴异常上面那个是真正的出错点（罪魁祸首），它上面的都是调用者（直接/间接），不是真凶。
- 第一行 `Traceback (most recent call last):` 是标题，找错时没用——从标题往后数，越靠后越接近真凶。
