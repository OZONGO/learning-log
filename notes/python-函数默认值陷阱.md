## 一、翻车现场与机制（AI 誊自本人口答）

### 现场①：预测陷阱输出
- **代码**：`def add_item(item, lst=[]): lst.append(item); return lst`
- **本人预测**：`['a']` / `['a', 'b']`
- **实际运行**：`['a']` / `['a', 'b']`

### 现场②：默认值在何时被创建
- **机制单选题**：默认 `[]` 是在 `def` 时创建，还是每次调用时创建？
- **本人答案**：`A. 制造工具时——程序执行到 def 那一行就造好了`

### 现场③：`__defaults__` 作为证据
- **追加探针**：`print(add_item.__defaults__)`
- **实际输出**：`(['a', 'b'],)`
- **解释**：`__defaults__` 是函数对象的属性，保存调用时使用的默认参数对象；本课里它直接证明了默认列表不是每次调用新造，而是长期挂在函数身上。

## 二、修复方案与传参机制（AI 誊自本人口答）

### 修复版
```python
def add_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

print(add_item("a")) #['a']
print(add_item("b")) #['b']
```

### 本人口答
- **修复思路**："默认值换成接收列表的变量而不是列表"
- **具体落点**："默认值放 `lst=None`，体内放 `if lst is None: lst = []`。因为如果没传参数，就新建一个列表。"
- **显式传参**："`add_item('x', my_list)` 因为传入 `my_list`，`if lst is None:` 为 False，`lst` 就是指向 `my_list`。"
- **输出预测**：`['a']` / `['b']` / `[1, 2, 3, 'x']`

### AI 点破（只基于上面原话补精确，不新增无关内容）
- `lst = []` 的"新"不是来自默认值，而是来自**函数体每次调用重新执行**。
- 调用者传入 `my_list` 后，`lst` 与 `my_list` 指向同一个列表对象；`append` 是原地修改，所以外部变量也跟着变。

## 三、收口公式（课堂原话）

签名上的东西（默认值）在造工具时求值一次；函数体里的东西每次用工具都重新执行。要把"每次都要新的"写到体内去。

## 四、本人填写

默认值陷阱最容易被我误解成：每次调用都会重新准备一个新的默认列表。

我用三句话讲清楚：
1. 默认值在函数创建时就执行；函数体在被调用时执行。
2. `lst=[]` 这个列表会挂在函数对象的 `__defaults__` 上，所以多次无参调用会复用同一个列表。
3. 修复版把默认值换成 `None`，函数体内再 `lst = []`，这样每次调用才真的新建列表。
