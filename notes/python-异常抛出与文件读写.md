## 一、这节课我学到了什么（誊自本人口答）

### 1. `raise`：第三条路，价值在"不可能被忽略"

- 抛出去之后"函数里剩下的代码不执行"、"没人接代码会死"——本人口述。准词记三节自查项：**函数当场结束，控制权跳到 `except`**。
- 判据（本人原话）：**"在知道怎么处理的层次上窄着 `except`，在'我处理不了、必须让上层知道'的地方 `raise` 出去；同时靠 `with` 保证无论走哪条路出去，收尾都干净。"** 这条比教练给因果的版本（`raise` 会让手写 `f.close()` 变成死代码）高一层，两条都成立。
- 选型判据本人当场自己说出的那句：**"都是预期内的事就不是程序有 bug"** —— 用户会犯的错 → 校验＋重问；程序自己犯的错（按签名绝不该出现的状态）→ `raise`，把事故钉在发生点。

### 2. 三个打开模式第一次动作的时刻表（本人口述，超出讲课深度）

| 模式 | open 成功那一刻做了什么 | 可逆性 |
|---|---|---|
| `"r"` | 查存在性 → 不存在抛 `FileNotFoundError`；存在则打开，指针停在 0 | 从不截断 |
| `"w"` | 检查＋创建＋**截断**一步到位——`open` 还没返回，文件已经 0 字节 | **就在这一刻，不可逆** |
| `"x"` | 检查＋创建，**原子**——不存在才创建；存在抛 `FileExistsError`；成功则文件为空 | 不动已有内容 |

### 3. `with`：保证收尾，且它保证的是"无论怎么出去"

- 本人原话：**"`with` 保证 `__exit__` 一定会被调用。"**
- 教练给的等价落地说法：**无论如何都 `close`（连带把缓冲区刷盘），你不用写、也不会漏**——正常走完、`return` 提前跑、抛异常炸出去，三种出路都关。
- 关键分辨：**`f` 出了 `with` 就作废，是因为句柄已关（`ValueError: I/O operation on closed file`），不是因为读到了末尾**。句柄作废 ≠ 数据丢失——已经读进内存的对象跟文件再无关系。

### 4. 两条本人自己提炼的规律（本课最值钱的部分）

- **发现一：字节层和文本层是两套独立的现实。**原话要点：文本层看到的内容是编码器翻译过的产物，翻译会在看不见的地方加东西（BOM、Windows 文本模式下 `\n` 变 `\r\n`、代码页转换）。**推论（本人事后自己接上）**："只要你在救援路径上启动一次文本解码，就是把编码器翻译产生的差异重新引入了一个本来要绕过翻译的流程。字节层的操作对所有内容都成立；文本层的操作只对'能被解释成文本的东西'成立——而坏文件恰恰是后者的反面。"
- **发现二：文件对象是带位置的游标，不是值的容器。**原话要点："读到哪指针就停到哪；第二次 `read()` 从当前位置往后读——指针已经在末尾了，所以返回 `''`。**文件没空，是你的读取位置空了。**" 想重来用 `f.seek(0)`。两条推论本人自己接了出来：`json.load(f)` 读过之后指针已在末尾；`load_book` 里的 `f` 出块作废是因为它是一次性的位置状态。

### 5. JSON 的两条规格

- **键只能是字符串。**整数键存进去、读回来变成字符串键，`data[1]` 当场 `KeyError: 1`——不报错地改变了类型、进而改变行为，属沉默型 bug 家族。
- **`ensure_ascii=False`** 决定中文在文件里是"张三"还是 `\u5f20\u4e09`。

### 6. traceback：真凶的定位规则要升级（本课最重要的一条订正）

本人的旧规矩（N003 第五节）是"**从标题往后数，越靠后越接近真凶**"。今天现场对账发现它**只对终端直跑成立**：

| | 终端 `python 脚本.py` | 调试控制台（VS Code F5 / debugpy，本人日常） |
|---|---|---|
| 第一行 | `Traceback (most recent call last):`（零信息） | `发生异常: ValueError`（**带异常类型**） |
| 帧顺序 | 调用入口在前、真凶在后 | **真凶在前**、调用入口在后 |

升级后的统一规则（两种格式都成立）：**真凶＝离异常类型那一行最近的那个 File 行。**终端里类型在末尾所以往**上**找；调试台里类型在开头所以往**下**找。其余 File 行是"谁把这次调用带进来的"。
旧措辞在 F5 环境下方向是反的，面试答"越靠后越接近真凶"会被抓。

### 7. 外部知识来源（本人口述，四项均可讲清语义）

| 用到 | 出处 |
|---|---|
| `"x"` 独占创建 | Python 官方文档 `open()` 的模式表 |
| `__exit__` | 上下文管理器协议的方法名，`with` 的实现机制，语言规范级 |
| `\ufeff`（BOM） | Unicode 标准的字节序标记，与 Python 无关 |
| `seek(0)` | 文件对象方法，Python IO 内建 |

> 备注：能解释语义才计入本人所有（"x"／`__exit__`／`bytes` 类型匹配三处当场口述过关）。查文档不是问题，**抄了讲不清**才是问题。

### `raise_with_lab.py` 五实验（预测先行，全部对账一致）

| # | 验什么 | 预测＝实测 |
|---|---|---|
| ① | `raise` 后同函数内语句不执行 | 屏幕只有一行 `接住： ...`，`print("会打吗")` 从未出现 |
| ② | 没人接就整个程序停 | 末行 `ValueError: ...`；完整 traceback 见下（帧顺序是 F5 格式） |
| ③ | `"w"` 在 `open` 那一刻截断 | 第二次只用 `"w"` 打开、一个字不写、立刻 close → 第三次 `"r"` 读出来是**空** |
| ④ | 文件指针停在末尾 | 第一次 `read()` 出 `a`/`b`/空行，第二次 `print` 出**空行**——本人连两个空行都预测到位 |

- **实验② traceback 原文（本人终端，F5）**：`发生异常: ValueError` 开头，`line 12, in ra2`（raise 处）排在 `line 14, in <module>`（调用处）**上面**——帧顺序与标准 CLI 相反，由此推出第一节第 6 条的升级规则。
- **`notes_lab.txt` 六字节事件（本人自己发现）**：写 `"a\nb\n"` 四个字符，盘上是 `61 0d 0a 62 0d 0a` 六个字节——Windows 文本模式做了 `\n`→`\r\n` 翻译。这条直接成了后面二进制备份的判据。

### `contacts_v2.py` 改造：DoD 六条逐项实测

删除 → `2` → `zs` → `删除成功` → 退出 → **重开 → `5-显示全部` 只剩李四、王五**；`cat contacts.json` 与读盘互证：`"zs"` 计数为 0、文件合法。首次运行（文件不存在）静默从 `{}` 起步，损坏测试走 `JSONDecodeError` 分支并留下备份。

**超出布置的自行改动（本人主动完成，三处）**：

1. `except` 收窄——`try` 只包 `int(t)` 一行，五个菜单分支整体挪出异常块。
2. `_backup_corrupt_file()` —— 损坏文件先另存 `*.brokenN` 再清空起步，避免下一次 `"w"` 把可抢救内容彻底抹掉。本人写进 docstring 的理由：**"如果不做这一步，下一次 `save_book` 就会把原文彻底抹掉。"**
3. docstring「设计取舍」段——写清"每次即存"的**代价**（每次写盘都是不可逆截断）与**换来**（中途崩溃/Ctrl-C 不丢数据），并据此说明 `q` 分支为何不需再存。

`except json.JSONDecodeError` 只接它、不用 `except ValueError`，本人在 DoD 注释里写明理由：`JSONDecodeError` 是 `ValueError` 的子类，宽接会连 `int(t)` 的错误一起吞。**接不住 vs 接太宽**这条线，从 N008 走到今天落地了。

### 两次"跑对了但原因是假的"（本课最贵的教训）

- **`broken2` 字节完全一致是巧合**：删掉 `encoding=` 但没加 `b`，Python 退回本机默认编码（Windows/3.13＝**GBK**）继续翻译。字节仍然一致来自两个**互相抵消**：换行 `\r\n`→`\n`→`\r\n`；UTF-8 字节按 GBK 解码再按 GBK 编码回去。**只要文件是纯 `\n` 换行，备份就会多出 `\r`；只要字节 GBK 解不动，救援当场崩。**
  → 铁律：**删掉 `encoding=` 不等于关掉翻译，只代表"用系统默认继续翻译"。要真正不翻译，只有二进制。**
- **`n += q`**：一次编辑把 `n += 1` 写成了 `n += q`（`q` 从没定义过）。`ast.parse` 通过——**语法合法，只有跑到那一行才炸**；而它躲在 `except FileExistsError` 里，**只有 `.broken1` 已存在时才执行**，所以"看起来一切正常"。
  → 铁律：**分支覆盖不到的地方，就是没测过的地方。**

### 设计原则：救援路径不能依赖被救对象是好的

`load_book` 与 `_backup_corrupt_file` 用同一套解码，等于要求"坏文件是好的"才能备份坏文件。两处改动的**先后顺序被这个原则锁死**：先把备份改成二进制，才谈得上把 `except` 放宽到 `UnicodeDecodeError`——否则放宽的那一刻，崩点只是从 `load_book` 搬到 `_backup_corrupt_file`。

### 教练错案三起（本档留档，不计学习者 miss）

1. **P1 复述第 3 题题面缺陷**：把"`num_check` 重问"和"用户输错"并列成两项，其实是同一件事，漏掉了真正要对照的"程序自身的 bug"。学习者按字面答"都不该 raise"，正确。重问后（用户输错 vs 绝不该出现的类型）答对。
2. **实验② 方向说反**：题干写"traceback 最后一行……以及它**下面**那一行指向文件·行号"。最后一行就是异常本身，底下什么都没有；File 行在其**上面**。与学习者 N003 已有笔记自相矛盾，学习者未编造，判为教练错案。
3. **误判崩点位置**：暗示"备份函数会自己崩在抢救路上"。实际是 `load_book` 在更早处抛 `UnicodeDecodeError`、`except json.JSONDecodeError` 不匹配、**备份函数从未被调用**。学习者答"同一个异常、同一个位置"已踩在这点上，收尾由教练订正。

## 三、我给自己提的醒（誊自本人口答＋当场订正）

- **措辞自查**：`raise` 之后不是"跳过"，是**函数当场结束、控制权跳到 `except`**（今天用了两次）。
- **概念自查**：`f` 出了 `with` 作废的原因是**句柄已关**，不是"游标在末尾"（P2 复述答对过，收工复述滑回）。
- **复述遗漏**：收工费曼**整块 JSON 没提**（键只能字符串、`ensure_ascii=False`）——下半节课的主件在复述里不存在。复述要覆盖"今天学的每一块"，不是只讲最有手感的那块。
- **习惯**：**说了 ≠ 做了**。讲清 `bytes` 类型匹配之后代码里一行没改；改完要用能证伪自己的一句话验（`type(raw)` → `<class 'bytes'>`）。
- **习惯**：删掉的 `encoding=` 不是"关掉"，是"换默认继续"。二进制的标志是**模式串里的 `b`**。
- **常识**：路径一律正斜杠。反斜杠里 `\b`、`\t`、`\n` 会被吃掉成控制字符，`\A` 这类只是侥幸保留原样＋`SyntaxWarning`。
- **常识**：`with` 块里不要再手写 `f.close()`——不是错，但它让读者以为关是你干的，而 `with` 的价值恰在这句话不该由你负责。
- **待办**：`_backup_corrupt_file()` 里 `while True` 只捕 `FileExistsError`，其他 `OSError`（目录不可写等）会穿出 `load_book`；明天开场说清"为什么它不会死循环、以及该不该再兜一层"。

## 四、一句话总结（本人填写）

> 今天学到的、之前不知道的那**一件**事。**只能写一件。**写不出来就说明今天没有一个清晰的收获。

> **誊写说明（2026-09-10 收工）**：本节第一、二句＝本人口述原话（AI 仅顺标点）；末段引申为 AI 补笔，已标注。

**raise 管的是控制流的脱身，with 管的是脱身之后不留垃圾。它们必须成对出现，因为异常传播路径和资源释放路径是同一条路——你不可能只保证其中一条。**

—— AI 补笔（对"必须成对"的精确化，本人核对）：`with` 保证的是**任何出路**都收尾——正常走完、`return`、`break`、`continue`、`raise`，五种都关，所以它并不依赖 `raise` 而存在。"成对"成立的方向是：**`with` 单独存在时只是省事；`raise` 一出现，`with` 就从事后清理升级成结构上的必需**。
