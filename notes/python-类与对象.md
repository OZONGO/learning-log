## 一、属性查找链与绑定（誊自 2026-09-16 口答 Q1）

`d.fetch()` 的完整查找（本人原话，六步）：

1. `d.__dict__`（实例字典）里有没有 `fetch`？——没有；
2. 去 `type(d)`，也就是 `Dog.__dict__` 里找——没有；
3. 按 `Dog.__mro__` 往上找：`Dog → Animal → object`；
4. 在 `Animal.__dict__` 里找到函数对象；
5. 因为是通过**实例**访问，触发**描述符协议，自动绑定 `self = d`**；
6. `d.fetch()` 最终等价于 `Animal.fetch(d)`——**`self` 是 d，方法体来自 Animal**。

类上拿 vs 实例上拿（本人对照，实测原文）：

```python
Dog.speak             # <function Animal.speak at 0x...>
Dog("旺柴").speak      # <bound method Animal.speak of <__main__.Dog object at 0x...>>
```

显示名跟着 Animal 走的原因（本人原话）："显示名用的是函数对象的 `__qualname__`，它记录的是**函数被定义的位置**，不是'通过哪个类访问到它'。`speak` 的方法体只写在 Animal 的类体里；`Dog.speak is Animal.speak` → `True`，就是同一个函数对象——Dog 只是通过 MRO 找到了它，**没有复制、没有改名**。"

> **AI 补**（术语钉牢）：绑定方法上另有两个把手——`__func__` 是函数本体、`__self__` 是绑定的实例（你在 class_lab 实验③自主补打过的 `bound.__self__` 就是它）。绑定**发生在从实例上取的那一刻**，取之前函数对象一直静静躺在 `Animal.__dict__` 里。

## 二、类属性 vs 实例属性：什么时候共享有害（誊自口答 Q2）

本人两句公式（原话）：

- **可变类属性＋原地修改＝共享污染**——所有实例没有自己的 `items`，读到的都是同一个类属性对象，`append` 原地改的就是它；
- **不可变类属性＋重新赋值＝不共享**——`+=` 对不可变对象会创建新对象，然后 `self.items = 新对象` **在实例自己的 `__dict__` 里建一个新属性，遮蔽了类属性**。

`+=` 的两副面孔（本人表）：

| 类型 | 走的方法 | 行为 | 共享？ |
|---|---|---|---|
| list | `__iadd__` | 原地扩展，返回 self | 改的就是类属性那个列表，**仍共享** |
| str | 无 `__iadd__`，走 `__add__` | 创建新字符串 | 赋给实例属性（重贴标签），**不共享** |

> **AI 补**（界线归宗）：同一个 `+=`，分水岭是**该类型有没有 `__iadd__`**——有则"顺着名字改对象"，无则"重贴标签"。这正是作用域课那条界线（重贴标签 vs 改内容）在 `self.` 上的重现，加一条类侧规则：**属性写入永远落在实例上（写落实例），读取才走查找链**。

## 三、`__new__` 与 `__init__`：创建分两站（誊自口答 Q3）

本人原话：`__new__` **负责创建实例，返回一个新对象**；`__init__` **负责初始化实例**，把属性填进去——收 `self`（已经创建好的实例）＋自定义参数，**必须返回 `None`**。所以"`__init__` 不是构造函数"：它拿到的是已经存在的对象，它只往里摆东西。子类定义了 `__init__`，父类那份**不会自动执行**。

## 四、继承：重写与 super()（誊自口答 Q4）

**重写＝盖住，不是删除**（本人原话）："重写只是在**子类字典**里放了一个同名的新函数，MRO 在子类这层先命中它，**父类的函数原地不动**。"

正向证据（实验①c 本人实测）：另建父类实例 `Animal("普通动物").speak()` 照样打出父类版"发出声音"——盖住只影响"从子类的链上找"，不影响父类原主。

**忘调 `super().__init__()` 为什么晚炸**（本人原话）："`ChildNoSuper.__init__` 只做了 `self.b = 2`，语法上没问题，**Python 不会检查'你是不是忘了调父类'**。坏数据藏起来了，**直到下游用到 `self.a`**（才炸）。"（实验②d：构造不炸、`describe()` 方法体内读 `self.a` 才炸——炸点离病灶隔一次调用，沉默型 bug 家族的新形态。）

**`super()` 的正解**（实验② ChildSuper 本人代码）：先 `super().__init__(a)` 让父类干完它的活，子类再写 `self.b = b`——**加菜，不换菜单**。

## 五、`__str__` / `__repr__`：回退矩阵（誊自口答 Q5）

三行走谁（本人表，实测见 inherit_lab 态1~3）：

| 表达式 | 走 |
|---|---|
| `print(p)` | `__str__` |
| `print([p])` | 列表内部对每个元素用 **`__repr__`** |
| `repr(p)` | `__repr__` |

回退方向（本人三条，方向题一错没犯）：

- `__str__` 缺失 → 回退到 `__repr__`：**有路**；
- `__repr__` 缺失 → 沿链上溯到 `object.__repr__`（默认地址格式）：**有路**；
- `__repr__` 缺失 → 回退到 `__str__`：**没路**。

写作标准（**本人自铸结论，原话**）："**`__repr__` 总是写；`__str__` 需要用户友好输出时再写。**"

> **AI 补**（机制出处）：单向回退不是规定，是拓扑事实——`object.__str__` 的默认实现就是转手调 `__repr__`，反方向没有这座桥。

## 六、`@property`：存储量与派生量（誊自口答 Q6+Q7）

**校验为什么必须挂存储量**（本人三理由，原话）：

1. **源头唯一**：所有 `area` 都是从 `r` 算出来的，守住 `r`，`area` 自动干净；
2. **入口全覆盖**：任何改 `r` 的路径（构造、赋值、内部计算）都走 `r.setter`；
3. **挂派生量守不住源头**：只挂 `area.setter`，`c.r = -5` 绕过它直接改存储量，派生量算出来还是错的。

**"无条件"的真面目**（本人精确限定，原话）："只要走公开接口（`c.r = ...`），校验无条件生效；**绕过公开接口（`c._r = ...`），Python 不兜底**。"

> **AI 补**（性质定性）：单下划线是**约定，不是强制**——property 是篱笆，不是墙；防的是无心之失，不防拆篱笆的人。真防线＝纪律＋测试（同 MP1"契约＋反向夹具"的路数）。你抽查答"入口全覆盖"时已把这层说中——"唯一入口"是**走约定这道门**的唯一，不是物理意义的唯一。

**什么量该存、什么量该算**（本人 Q7，原话）：

- **该存的**：独立、不可推导的量（如 `r`）——存储量是"事实来源"，必须精确、直接；
- **该算的**：可由存储量推导的量（如 `area`）——不存、每次现读现算，**保证永远和 r 一致**；
- **为什么不能都存**："同一事实存两份，每个写入点都要同步更新另一个，改 r 忘了改 area，或反过来，**两份数据打架**。"——与通讯录课"不要维护两个字典"同一条原则的类版本。
- （反解注：半径与面积数学上可互推，但 `r = sqrt(area/π)` 是反解、有浮点误差、且丢符号信息——**正推该算、反推不该存**，存的是最上游的那个事实。）
