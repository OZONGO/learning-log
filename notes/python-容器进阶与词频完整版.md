## 二、概念卡（誊自 2026-09-05 口答）

**卡 1：set 是什么、为什么快**
- 本人原话（费曼）："因为 set 装进去的内容不可变，用哈希表存储，可以直接查询用内存地址。"
- AI 批注：哈希直查核心对；一处要拧准——**不可变的是"准入资格"**（只有不可变的东西能装进去），set 本身是可变的（`add` 就是在改它）。set＝只有键、没有值的 dict，CPython 里就是一张只存键的哈希表。

**卡 2：准入规矩与 dict 键同源**
- 本人原话（D 场收尾）："因为列表可变所以无法被集合储存。"
- AI 批注：方向对，精确一步——不是"不能储存"，是**"算不出该放哪个格子"**：列表会被改 → 编号不稳 → 表不收它。与 dict 键是同一条规矩的两种说法。实测 `s.add([1, 2])` 报 `TypeError: unhashable type: 'list'`（与 9/4 dict 键实测同一条原文）。

**卡 3：嵌套剥层**
- 本人原话（费曼）："第一层得到的是键 Alice 的值（列表），第二层是列表的第二个值。"
- AI 点破（元问题，要能先行脱口而出）：**每剥一层，问自己"现在手里拿的是什么类型？"**——dict 方括号找**键**、list 方括号找**位置**。实证：`scores[0]` → `KeyError: 0`（`0` 被当成不存在的键名，不是"第 0 个"）。

**卡 4：推导式读法**
- 本人原话（费曼）："从 words 中去除每个 w，如果不是只包含数字字符的字符串，去掉首尾的符号，将大写变成小写。"
- AI 批注：链路全对，一个词要改："去除"→"**收**进新列表"——推导式是收集，被丢弃的是 `if` 拦下的。另注意：`isdigit` 检查的是**原始的 w**（先过滤后清洗的语义）；"只包含数字字符的字符串"——字符层措辞持续立住。

**卡 5：Counter＝dict 的子类**
- 本人预测："大概长 dict 那样"（结构猜对）。
- 实测与 AI 补充：`Counter({'a': 3, ...})` 长得像 dict 不是巧合——**Counter 就是 dict 的子类**，`get`/`in`/`items()` 全继承，只是把"缺的键当 0"特化，又加了 `most_common`。`most_common(5)` 返回**列表装元组** `[(词, 次数), ...]`，与手写 `sorted(counts.items(), key=lambda item: item[1], reverse=True)[:5]` 产出**同构**——先会手写再认工具，是今天的立意。

**卡 6：报错原文与词汇**
- 今日新增词汇：**subscriptable＝"支持下标"**（subscript＝下标）。`'set' object is not subscriptable`＝set 不支持下标操作。
- AI 点破：报错原文的两个作用——①证明你**真的跑过**（AI 复述不出你没跑过的报错）；②**逐字读报错**是排 bug 第一技能（`unhashable` 算不出编号 vs `immutable` 不能改，一词之差修法不同）。报错词族认全 `unhashable` / `not subscriptable` / `not callable`，一半 TypeError 就不吓人了。

## 三、今日踩的坑（誊自当日口答＋实测，AI 点破处注明）

**坑 1：`{}` 不是空 set**
- 实际是：`{}` 被语法划给了空**字典**，空 set 只能写 `set()`。
- 当日情况：预测题即答对（type({}) → dict），未亲身踩，防它日手滑。

**坑 2：set 无下标**
- 现象：`s[0]`。
- 实测报错：`TypeError: 'set' object is not subscriptable`。
- 根源：set 无序 → 没有"第 0 格"的概念 → 下标操作对它无意义，不是 Python 小气。

**坑 3：dict 的方括号找键，不找位置**
- 现象：`scores[0]`。
- 实测报错：`KeyError: 0`——`0` 被当作不存在的**键名**去查。
- 以后怎么避免：同一种 `[]`，list 按位置、dict 按键；嵌套剥层时每层先问"手里是什么类型"。

**坑 4：推导式里的 W1 惯性（AI 评审指出两条，本人已确认改法）**
- 现象①：`[words[x].strip(...) for x in range(len(words))]`——把 W1 的 range 姿势带进推导式。推导式是**造新列表**，没有"写回"需求，直接 `for w in words`；`strip().lower()` 还能链起来。
- 现象②：循环变量命名 `counts2`，两行后 `counts2` 又变成 Counter 变量——名字打架。**名字是给读者（三个月后的自己）的路标**，循环变量叫 `w` 就好。

**坑 5：set 的打印顺序巧合**
- 现象：`{'the', 'and', 'men'}` 恰好像插入顺序。
- 实际是：字符串哈希值每次运行可能不同，顺序会洗牌。**永远不依赖 set 的顺序**（预测题当日已答对"没有保证顺序"，实测看着有序只是巧合）。

**坑 6：【AI 的坑，如实记录】教练规格乌龙**
- 现象：D 场布置"补大小写合并、剥标点"，但 word_freq2.py **早已带 strip+lower**——AI 把笔记里假设性的问题（"不做会怎样"）误读成了"代码里没做"。
- 结果：学员榜单与 9/4 完全一致却说不清该不该变；真正新增只有 isdigit 闸＋Counter。
- 教训：**布置任务前先读现有代码**（教练也要先看后说）。学员当时的正确产出＝榜单零变化＋`3` 从总表消失（`counts2.get("3")` → `None` 实证）。
