# review/ Anki 式间隔重复复习系统

> 起草：AI ｜ 内容确认：OZONGO
> 2026-09-10 由原「艾宾浩斯固定间隔」系统整体改造为 **Anki 式自适应调度**；仍叠加在现有「待复述问题清单＋弱点清单」之上，不替代任何现有流程。
> 依据：Anki/SM-2 自适应算法（四档评分 Again/Hard/Good/Easy ＋ 简易度因子 EF 驱动的自适应间隔）＋主动回忆（Active Recall）＋最小信息原则（Minimum Information）。
> 每天约 15 分钟，嵌入学习会话开场（先清到期复习，再开新课）。

## 与旧系统的一句话区别

- **旧**＝固定阶梯（1/2/4/7/15/30/60 天）＋三档评分（记得/模糊/忘了），所有卡走同一条梯子。
- **新**＝Anki 式自适应：每张卡独立维护自己的「间隔(天)」与「简易度 EF」，按四档评分实时算出下一次到期日。答得越轻松，间隔涨得越快；越吃力，间隔越短、EF 越低。卡与卡不再齐步走。

## 文件职责

| 文件 | 角色 | 维护方 |
|---|---|---|
| queue.md | 中央复习队列——间隔/EF/到期/状态的**唯一活跃真相源**（Anki 字段） | AI（教练技能读写） |
| log.md | 复习日志（追加式，永不改历史行；事件日期含时分 `YYYY-MM-DD HH:MM`——与 queue/weaknesses 的纯日期解析契约相区分） | AI |
| weaknesses.md | 弱点登记表 WK-xxx（跨笔记集中，含已结案留档） | AI |
| README.md | 本说明 | AI |

## 卡片模型（Anki 概念 → 本系统落地）

| Anki 概念 | 本系统落地 |
|---|---|
| Note（笔记） | 一篇 `notes/*.md`，或一条弱点 `WK-xxx` |
| Card（卡片） | 笔记零节清单里的每一道题 → 一张卡；每条弱点 → 一张卡（弱点卡） |
| 卡型 Basic / Cloze | 本系统以「问答卡」为主（正面＝题、背面＝答案）；固定表述类可用「填空卡」（Cloze，挖空关键术语） |
| 学习阶段 Learning | 新卡入队当天起＝学习期；首测通过后转入复习期 |
| 复习阶段 Review | 带「间隔(天)」与「EF」的常规复习 |
| 重学阶段 Relearning | 评「重来」失败后，回到 1 天间隔重学 |
| 水蛭卡 Leech | 反复记不住的卡 → 打标记，拆卡/重写/加助记（见下） |

> 原子化底线（Anki 最小信息原则）：**一卡一事实**——一道题只考一个点，答案能在约 20 字内说清；一道题若塞了两个点，拆成两张卡。

## 四档评分与调度规则（每次复习后更新 queue.md）

每次复习**先自己回想，再看答案**（主动回忆），然后按回忆质量落入四档之一：

| 评分档 | Anki 原名 | 含义 | 简易度 EF | 间隔变化 |
|---|---|---|---|---|
| 重来 | Again | 完全想不起 / 核心答不出 | EF −0.20 | 间隔**重置为 1 天**（进入重学）；失误次数 **+1** |
| 困难 | Hard | 答上来了，但很吃力、需提示 | EF −0.15 | 间隔 **×1.2**（至少 1 天） |
| 良好 | Good | 正常答清、达笔记通关标准 | 不变 | 间隔 **×EF**（新卡首次「良好」＝毕业间隔 **1 天**） |
| 简单 | Easy | 秒答、毫无迟疑、超出预期 | EF +0.15 | 间隔 **×EF×1.3**（新卡首次「简单」＝**4 天**） |

补充规则：

- **EF 下限 1.3**（无上限）。新卡初始 EF = 2.5。
- **新卡（学习期）评「重来」不扣 EF**——对应 Anki「学习阶段的失败不反映真实难度」，避免卡片卡在"低间隔地狱"。
- **最大间隔 60 天**：某卡间隔达到/超过 60 天 → 视为**成熟**，移入 queue.md 底部「已成熟（暂停）」区留档（阶段验收/模拟面试可抽）。这是对 Anki「最大间隔 ＋ suspend」的落地，**承接旧系统的"毕业"**。
- **逾期补偿**：卡逾期 ≥1 天才复习、且评「良好/简单」→ 该次间隔额外 **×1.1**（对应 Anki 对"迟到但记得"的卡给间隔加成）。
- **复习次数**：终身累计只增不减；**失误次数（lapse）** 仅用于水蛭判定（见下）。
- 说明：旧系统的「连续两次记得 → 档位 +2」加速规则**已删除**——其作用由 Anki 的「简单」档自然承担（间隔 ×EF×1.3 且 EF 上升）。

## 水蛭卡（Leech）机制（Anki 独有，本期新增）

- **判定**：某卡累计评「重来」达 **4 次** → 标记为水蛭卡，状态改 `水蛭卡`。
- **处置（三选一，当场做完）**：① **拆卡**——把大题拆成更小的原子题；② **重写**——换更明确的提问、补语境；③ **加助记**——加一条钩子/口诀/最小示例。做完后失误次数归零、EF 重置 2.5，重新入队。
- **禁止**：无视它继续硬刷。Anki 官方立场明确——水蛭卡说明**卡本身设计有问题**，不是"多背几遍"能解决的。

## 每日流程（会话开场，约 15 分钟）

1. 教练读 queue.md，抽出「下次到期 ≤ 今天」的卡（逾期一并算到期），并按到期日排序（逾期最久的先测——对应 Anki 复习排序）。
2. 学习者**先自己回想，再看答案、合上代码与笔记脱稿口答**：
   - 笔记卡＝**抽题制**：教练按「入队前置检验」从零节挑**最多 3 道核心题**（机制/易错优先），答清即整卡过关；其余题目降级为学习者自查项，不逐题问答。
     只抽**可迁移知识**（概念/机制/陷阱/选型/习惯）；**自己代码的实现细节**（变量职责、分支结构、行号位置）不抽——代码本身即记录，回看即得，"能逐行讲自己的代码"归阶段验收与模拟面试的职能。
   - **题面写法（2026-09-10 增，用户三次同类反馈后定规）**：题面**直接问知识点**，**不得指向具体代码**——不引用"你代码里的某一行／某个函数／变量名／实验①②③／修复版／当时那个例子"。判定标准：**若这题必须回看代码原文才能作答，它就不合格**（回看即得的东西不证明记忆）。同一知识点改用纯概念问法重出。
   - 弱点卡＝用自己的话讲清该弱点＋举一个例子说明它怎么表现（自己代码里的例子或当场构造均可；**出处性细节永不考**——哪天/哪题/哪次会话归 Done Log，不进复习标准）。
   - **每日上限（Anki 剂量控制）**：新卡接入 ≤3 张/天；复习张数不限但**全流程硬上限 15 分钟，到点即停**；未清的卡顺延下次，不积欠、不补课。复习挤占新课时间＝系统违约。
3. 教练对每张卡落**四档之一**（重来/困难/良好/简单），按上方规则在 queue.md 更新（间隔/EF/上次复习=今天/下次到期/复习次数/失误/状态）；涉及弱点时同步 weaknesses.md（评「重来」→ 状态 recurred；新暴露 → 登记新 WK 并入队）；并向 log.md 表头下插入一行。
4. 清完到期卡再开新课。收尾 git 由用户本人执行：
   `git add -A && git commit -m "review: 清 X 张到期卡（重来A/困难B/良好C/简单D）" && git push`
5. 与看板 0.9 定例的关系：本流程是 0.9 的**升级**——从「每场全量自测最新一篇」升级为「按到期清单自测」，最新笔记几乎每天在到期名单里（自然覆盖），旧笔记按 Anki 间隔到期才测。
6. **学习者否决权**：学习者明确否决过的题面/题型，之后**不再作为考题出现**——该知识点移入自查项或阶段验收/模拟面试范围，log.md 摘要中留否决记录；若被否决的题正对应 open 弱点卡，以否决记录结案（status 改 resolved、结案日填当日、备注"否决结案"），避免到期卡"必须测又不能问"的死锁。**否决效力及于题面写法**：以具体代码字面量为锚点的题面（如"把默认值换成 None"）一经否决即永久禁入，该知识点改用纯概念问法重出——**题面禁入 ≠ 知识点免考**。
7. **水蛭处置**：复习中若某卡触发水蛭阈值，当场停下按上文「处置」三选一改造该卡，再继续。

## 入队规则

- **入队前置检验（先于以下所有条目执行）**：凡入卡（笔记零节清单、弱点卡）前先问「这个内容一个月后还值得考吗？」——只收**概念、机制、选型、易错模式、习惯**；会话传记性细节（具体哪天的哪道题、对话出处、排查日期）不入卡，那些是 Done Log 的活。
- **原子化**：入卡时即按「一卡一事实」拆分；能拆就拆。
- **新笔记**：成文（含零节清单，须先过上方检验）当天，AI 在文件头加 frontmatter（id 顺延、created=当天、weakness_ids=[]），queue.md 表尾追加一行：**间隔 1 天、EF 2.5、失误 0、下次到期 = 明天、状态 新学**。
- **新弱点**：会话/练习/面试中发现 → weaknesses.md 追加行（下一 WK 号、严重度 低/中/高、状态 open），queue.md 追加弱点卡（同新卡字段）。
- **弱点结案**：对应卡连续两次「良好/简单」且无复现 → 状态改 resolved、填结案日、卡片移出活跃队列。
- **面试遗忘点**：interviews/ 记录中「连续两次答错的同类题」或新盲区 → 生成新弱点卡入队（把 06 模板"标红强制进下周计划"落为可排程的卡）。

## 周复盘联动（周日，填 06 第六节）

- 执行率 = 本周已清到期卡 / 本周到期卡；四档分布（重来/困难/良好/简单）；EF 均值走势；弱点新增/结案/复现；水蛭卡数量。
- 到期未清的卡自动滚入下周（队列不改，复盘只记趋势）。
