## 本周学到什么（本人自述，2026-10-01 口述原话）

1. **日期校验的"两道关卡两把尺子"（parse 段）**：关卡一是自己写的**形状关**——长度恰好 10、第 4/7 位是 `-`、三段全是 ASCII 数字；关卡二**交给库**（`date.fromisoformat`）只问历法（有没有 13 月、2 月有没有 30 号、闰年怎么算）。为什么不能一个库函数了事：**库只保证"我这套方言能读通"，不保证"你的契约只允许哪一种字面"**——`fromisoformat` 吃 basic 格式和 ISO 周日期，`strptime` 吃不补零和全角年份；同一天只要长出第二种字面，dict 分组就裂。**两把尺子**：`date` 用 `isascii() and isdigit()` 当字符集过滤器，方向是"先过滤、再让库判数值合法性"——**反过来写就是 9/21 那条误放病根**；`week` 的尺子判**字面规范**而非"能不能解析"（`W`＋无前导零 ASCII 数字＋上界 `W28`），并且**选拒绝不选归一**：归一等于解析器悄悄改数据，文件里的值和内存里的值不一致，出错时无从对照，比幽灵分组更难查。顺带 `hours` 的尺子：`isfinite`＋非负，因为 `nan`/`inf` 能无声通过 `float()`，把整周合计污染掉还不报错。
2. **Make 与 requirements.txt 的分工**：两个都不是"专业项目该有的两件套"，而是各服务一个需求的工具，**判据是需求现在存不存在**。Makefile 把"怎么跑项目"从 README／口头／记忆变成仓库内可执行入口——但 MP1 只有一个 CLI 入口、命令少、README 已列全、没有跨项目跨人跨 agent 的反复调用，而 Windows 不自带 `make`，新增工具依赖收益不抵代价；requirements.txt 靠钉死第三方依赖版本换可复现——但 MP1 零第三方依赖，无可钉之物，**交空文件等于"为过审计造实物"**。关键在两条裁决都落了**触发条件**（同一组命令被多项目/多人/agent 反复调用→补 Makefile；出现任何非标准库 import→先 venv 再 `pip freeze`）——"不补"因此不是遗忘，而是带判据、带触发条件的常设裁决。**meta 一句：没有实物可以是正确答案，前提是判据写在纸上。**
3. **（半条）Harness 六失败模式↔六工件**：只能讲骨架——harness-lab 把同一个任务提示词分别喂给 weak 和 strong 两套 harness，弱侧会以几种典型方式失败，强侧用一一对应的工件堵住（AGENTS.md 立规矩、check.py 把验收变成可执行、feature_list.json 固化特性清单——**这三个角色是按文件名推的，不是笔记原文**）。**但六种失败模式具体是哪六个，我离开笔记列不全——这条过"理念关"，过不了"清单关"。**

## 卡壳记录（本周最大的困难 + 怎么解决的）

1. **9/28 反向 grep 报假绿（模式串漏反引号）**——**现象**：把 TD-1 正文从 `parse_sessions.py` 搬进 `aggregate.py` 后做指针自查，反向 grep README 确认旧指针还在不在，模式串取 `'parse_sessions.py 末尾技术债'`，零命中，据此报绿"指针已改准"。**排查**：T36 判卷当场查出两个假指针仍在原地（`README.md:64` 指向的正文已搬走；`parse_sessions.py:74` 的"见 2026-09-11 补记"锚的是另一件事）；复跑才发现 README 原文里文件名**带反引号**，模式串没算这个字符——旧指针明明在文件里，这个模式却永远搜不到它。**根因两层**：明层是 WK010——改完正文没打开实物核对，凭"改过了"的记忆下结论；暗层是**探针自身带病**——模式串不容错反引号时，零命中有两种解释（"内容真没了"和"模式串压根搜不到"），**同一份输出两种解释还硬要下结论，就把"没搜到"读成了"已清"**。**修复**：①两个假指针＋`sessions.md` 三行过期契约陈述当场订正，WK010 按新卡字段重开（`resolved`→`recurred`）；②当场立规矩——改指针必做反向 grep，命中的必须是**真锚点**，同一份输出有两种解释即探针不合格；③该规矩在 9/30 复测里补全成可执行动作并过关：模式串要容错反引号／全角括号／强调符，或换稳定子串（只搜 `TD-1`），或干脆打开目标文件看那段——**零命中是负证据，不够格证明"已清"**。
